附属模组

面向附属模组作者的 Java API：调用一个方法，就能添加自己的日志节点、世界、星座、事件和星门条件，Fabric 与 NeoForge 通用。

Unbound 为附属模组提供公开的 Java API。附属模组只需调用一个方法，就能把自己的内容接入本模组的各个系统—— 日志节点、火箭可去的世界、星座、世界事件、星门条件、气候区——还能读取它们的状态、监听它们的事件。不需要 Mixin，不需要访问加宽器（access widener），也不必照抄本模组的逻辑。

  • 约定的范围是 me.moltea.unbound.api 包及其子包。模组中的其他一切都属于内部实现，任何版本都可能改动。
  • API 有自己的版本号——UnboundApi.VERSION（当前为 1.1.0，遵循语义化版本）：修改或移除方法时升主版本号，新增方法时升次版本号；要移除的内容至少提前一个次版本标记为 @Deprecated。
  • Minecraft 26.3 与 1.21.1 上是同一套 API，Fabric 与 NeoForge 皆然：方法签名不随游戏版本变化，变的只有游戏自身的类型（例如 26.3 上的 Identifier 在 1.21.1 上是 ResourceLocation）。请针对你所用游戏版本的模组 jar 构建附属模组。
  • 该包的 Javadoc 为英文；总览见 api/package-info.java。
  • 你自己的方块、物品和生物照常注册在你的命名空间里；API 通过 id 或提供器（supplier）把它们接入本模组的系统。

所有领域通用的规则：

  • 注册是以 AddonContext 为第一个参数的静态方法。它们只在 register 内、配合其自身的上下文时有效；否则会抛出 IllegalStateException。
  • Id。各种东西用 Identifier 命名：本模组的——<mod id>:mars、<mod id>:solar_eclipse；你的——ctx.id("path")。进度钥匙是字符串；日志节点的 id 同时也是它的进度钥匙。
  • 你的内容的文本是你命名空间中的翻译键（各节下方列出）。缺少翻译时，模组会把路径转成文字显示，而不是显示原始键名。
  • 事件是各领域 <Area>Events 类中的字段。它们在服务器上触发，每次发生只触发一次；没人监听的事件不产生任何开销。
  • 机器的能量、流体和物品走各加载器自己的标准（Fabric 上为 Team Reborn Energy 与 Fabric Transfer，NeoForge 上为 capability）——见“兼容性”。它们没有单独的 API。

日志

api.journal 包。你自己的星辰日志章节与节点；目标；检查与授予进度钥匙。

  • 章节会成为排在本模组章节之后的标签页；节点在画布上的位置按其连线自动排布，与本模组的节点一样。
  • 目标：granted()（由你的代码授予）、item、items、key、either、alone、custom（节点开放期间每秒检查一次）。
  • 服务器端查询：Journal.has、Journal.grant、Journal.state；客户端——ClientJournal.has。
  • 事件：KEY_GRANTED、NODE_COMPLETED。
  • 文本：guide.<namespace>.chapter.<path>、guide.<namespace>.node.<path>.title|task|text。

旅行

api.travel 包。为你的维度设一个目的地：火箭、裂隙梭舟或下潜钟可以飞往那里、着陆并返回，与本模组的世界一样；在星辰之路上，它在星图上有自己的星球，如果愿意，还可以在供星舰航行的太阳系中出现。

  • 维度本身（生成器、带重力、空气和温度的维度类型）由你自己的数据定义。
  • 带发现钥匙的目的地在玩家获得该钥匙前保持隐藏；可由你的代码、日志节点或星空授予。
  • 查询：Travel.destinations、Travel.destination(id)、Travel.destinationOf(dimension)。
  • 事件：LAUNCH、LANDING（带首次着陆标记）、SHIP_TRAVEL（星舰离开或进入世界、跃迁、驶上远方之路或进行星际跃迁）。
  • 文本与图片：名称 destination.<namespace>.<path> 及 ….facts；地表地图 textures/space/<path>.png；梭舟与下潜钟窗口贴图 passage/<path>。

星空

api.sky 包。在天文望远镜的星空中加入你自己的星座、天体（卫星、行星）或深空天体（星云、星团、星系）。

  • 天体或深空天体可以等待钥匙（requires）；连成的星座会授予你的钥匙（grants）。
  • 查询：hasCompleted、hasDiscovered、进度钥匙、所有星座与天体的列表。
  • 事件：CONSTELLATION_COMPLETED、BODY_DISCOVERED。
  • 文本：constellation.<namespace>.<path>、sky_body.<namespace>.<path>、sky_sight.<namespace>.<path>。

世界事件与天气

api.worldevent 包。在任意世界——本模组的、你的或原版的——加入一种罕见的世界事件或天气，由现成效果（天空与雾的颜色、日光、粒子、风、冰雹、掉落物、群落、声音）和你自己的代码组合而成。

  • 环境效果按 id 指定属性，在本模组支持的所有 Minecraft 版本上都一样： Effects.scale(Identifier.withDefaultNamespace("visual/fog_end_distance"), Effects.Op.MULTIPLY, 0.4F)、tint、recolor、flag （API 1.1.0）。使用游戏 EnvironmentAttribute 类型的旧写法只存在于 Minecraft 26.x，且已弃用。
  • 你自己的效果每 every 刻运行一次，并且只在有玩家在场时运行。
  • 本模组的命令可按 id 开始和停止你的事件：<command> event <namespace>:<path>。
  • 查询：running、isRunning、strength、start、stop。
  • 事件：EVENT_STARTED、EVENT_ENDED、WEATHER_STARTED、WEATHER_ENDED。
  • 文本：event.<namespace>.<path>.name|hint、weather.<namespace>.<path>。

星门与生物

api.gate 与 api.creature 包。为任意世界的星门苏醒加入你自己的条件；为你自己的世界设定星门规则；主宰事件与生物标签。

  • 条件会叠加：全部满足时星门才会苏醒。你的条件在星门窗口中显示为一行，带勾选标记。
  • 查询：Gates.conditions、Gates.worthy、Bosses.isBoss、Bosses.rank。
  • 事件：GateEvents.AWAKENED、GateEvents.TRAVELED、CreatureEvents.BOSS_SUMMONED、CreatureEvents.BOSS_DEFEATED。
  • 标签：acid_immune——酸液不会灼伤该生物；c:bosses——首领通用标签。

空气、气候与重力

api.life 包。有没有空气、有多热、实体感受到多大的重力、宇航服里还有什么——以及改变它们。

  • 查询：Environment.breathes、airless、localHeat、gravity、weightless；Spacesuit.oxygen、charge、modules。
  • 修饰器（OXYGEN_USE、CLIMATE、GRAVITY）串联执行：每个监听器拿到的是上一个监听器的值。GRAVITY 在两端都会运行—— 只依据客户端和服务器都能看到的东西做判断（手持物品、盔甲、状态效果）。
  • 区域：自定义重力的球形区域、维度的气候规则；你自己的供气方块（holdAirSphere、holdRoomAir）能像本模组的氧气穹顶或送风机那样保持空气。
  • 标签：方块 airtight、needs_air、magnetic；物品 pressure_bound、hydrous_minerals。
