附属模组

面向附属模组作者的 Java API：调用一个方法，就能添加自己的日志节点、世界、星座、事件和星门条件，Fabric 与 NeoForge 通用。

Unbound 为附属模组提供公开的 Java API。附属模组只需调用一个方法，就能把自己的内容接入本模组的各个系统—— 日志节点、火箭可去的世界、星座、世界事件、星门条件、气候区、拥有自己身体的整个原住民民族或给民族的任务、带有本模组招式与饲养的生物、带有本模组血条的首领、带有精通的武器、机器的控制台、宇航服模块、光谱实验室的物质、射电源、通往你的世界的裂隙或熔口、开放太空的天体、带有自己模型的飞船船体、飞船模块、空间站委托、HUD 元素或高光时刻—— 还能读取它们的状态、监听它们的事件。有些内容根本不需要 API：它们通过游戏数据开放（见「通过数据开放」），模组的九个目录还接受附属模组 JSON 文件中的条目（见「用附属模组的文件扩充模组目录」）。不需要 Mixin，不需要访问加宽器（access widener），也不必照抄本模组的逻辑。

  • 约定的范围是 me.moltea.unbound.api 包及其子包。模组中的其他一切都属于内部实现，任何版本都可能改动。
  • API 有自己的版本号——UnboundApi.VERSION（当前为 1.5.0，遵循语义化版本）：修改或移除方法时升主版本号，新增方法时升次版本号；要移除的内容至少提前一个次版本标记为 @Deprecated。
  • Minecraft 26.3、1.21.1 与 1.20.1 上是同一套 API，Fabric 与 NeoForge 皆然：方法签名不随游戏版本变化，变的只有游戏自身的类型（例如 26.3 上的 Identifier 在 1.21.1 上是 ResourceLocation）。请针对你所用游戏版本的模组 jar 构建附属模组。
  • 该包的 Javadoc 为英文；总览见 api/package-info.java。
  • 你自己的方块、物品和生物照常注册在你的命名空间里；API 通过 id 或提供器（supplier）把它们接入本模组的系统。

快速上手

实现 UnboundAddon。每次游戏启动时，模组会在客户端和专用服务器上各调用一次 register，且在读取自身列表之前调用—— 模组的加载顺序无关紧要。附属模组要和本模组一样，装在服务器和每位玩家那里。

  • Fabric——在你的 fabric.mod.json 中，把这个类写在与模组 id 同名的入口点键下（与模组命令是同一个词；在代码中为 UnboundApi.modId()）：
  • NeoForge——无需声明：你的模组中直接实现 UnboundAddon、并带有公开无参构造器的类会被自动找到。

所有领域通用的规则：

  • 注册是以 AddonContext 为第一个参数的静态方法。它们只在 register 内、配合其自身的上下文时有效；否则会抛出 IllegalStateException。
  • Id。各种东西用 Identifier 命名：本模组的——<mod id>:mars、<mod id>:solar_eclipse；你的——ctx.id("path")。进度钥匙是字符串；日志节点的 id 同时也是它的进度钥匙。
  • 你的内容的文本是你命名空间中的翻译键（各节下方列出）。缺少翻译时，模组会把路径转成文字显示，而不是显示原始键名。
  • 事件是各领域 <Area>Events 类中的字段。它们在服务器上触发，每次发生只触发一次；没人监听的事件不产生任何开销。
  • 机器的能量、流体和物品走各加载器自己的标准（Fabric 上为 Team Reborn Energy 与 Fabric Transfer，NeoForge 上为 capability）——见“兼容性”。它们没有单独的 API。

日志

api.journal 包。你自己的星辰日志章节与节点；目标；检查与授予进度钥匙。

  • 章节会成为排在本模组章节之后的标签页；节点在画布上的位置按其连线自动排布，与本模组的节点一样。
  • 目标：granted()（由你的代码授予）、item、items、key、either、alone、custom（节点开放期间每秒检查一次）。
  • 服务器端查询：Journal.has、Journal.grant、Journal.state；客户端——ClientJournal.has。
  • 事件：KEY_GRANTED、NODE_COMPLETED。
  • 文本：guide.<namespace>.chapter.<path>、guide.<namespace>.node.<path>.title|task|text。

旅行

api.travel 包。为你的维度设一个目的地：火箭、裂隙梭舟或下潜钟可以飞往那里、着陆并返回，与本模组的世界一样；在星辰之路上，它在星图上有自己的星球，如果愿意，还可以在供星舰航行的太阳系中出现。

  • 维度本身（生成器、带重力、空气和温度的维度类型）由你自己的数据定义。
  • 带发现钥匙的目的地在玩家获得该钥匙前保持隐藏；可由你的代码、日志节点或星空授予。
  • 查询：Travel.destinations、Travel.destination(id)、Travel.destinationOf(dimension)。
  • 事件：LAUNCH、LANDING（带首次着陆标记）、SHIP_TRAVEL（星舰离开或进入世界、跃迁、驶上远方之路或进行星际跃迁）。
  • 文本与图片：名称 destination.<namespace>.<path> 及 ….facts；地表地图 textures/space/<path>.png；梭舟与下潜钟窗口贴图 passage/<path>。

星空

api.sky 包。在天文望远镜的星空中加入你自己的星座、天体（卫星、行星）或深空天体（星云、星团、星系）。

  • 天体或深空天体可以等待钥匙（requires）；连成的星座会授予你的钥匙（grants）。
  • 查询：hasCompleted、hasDiscovered、进度钥匙、所有星座与天体的列表。
  • 事件：CONSTELLATION_COMPLETED、BODY_DISCOVERED。
  • 文本：constellation.<namespace>.<path>、sky_body.<namespace>.<path>、sky_sight.<namespace>.<path>。

裂隙与熔口

包 api.sky。在末地天空中加入你自己的裂隙，在下界岩浆中加入你自己的熔口。玩家用模组的裂隙镜和熔岩镜寻找它们，方式与模组自带的八处完全相同—— 追随虚空火花并撕开缝线，敲击岩浆并按它的脉搏节奏敲碎硬壳——而它们背后的世界就是你在裂隙梭舟或下潜钟路线上的目的地。

  • 裂隙悬于地平线上方 20–82°，熔口位于地平线下方 15–82°；请远离模组自带的位置（方位角 55、165、250、330 与 40、130、225、310）—— 过近的位置会在 register() 时被拒绝。
  • leadsTo 接受同一路线的目的地（裂隙用 Craft.RIFT_SHUTTLE，熔口用 Craft.DIVING_BELL）；找到该处即授予目的地的发现键。 fromStage(n) 等待末地或下界阶段；requires 和 grants 与天空中的用法相同。
  • 查询：riftKey、ventKey、hasFoundRift、hasFoundVent、rifts()、vents()、beyondRift、belowVent。
  • 文本：sky_rift.<命名空间>.<路径>（.facts、.clue）、sky_vent.<命名空间>.<路径>；图片——你命名空间中的 GUI 精灵 observatory/rift/<路径>、observatory/vent/<路径> 与 <路径>_crust。
  • 你的裂隙和熔口不会推进末地与下界的阶段——如有需要，请用 Stages.advance 自行计入。

世界事件与天气

api.worldevent 包。在任意世界——本模组的、你的或原版的——加入一种罕见的世界事件或天气，由现成效果（天空与雾的颜色、日光、粒子、风、冰雹、掉落物、群落、声音）和你自己的代码组合而成。

  • 环境效果按 id 指定属性，在本模组支持的所有 Minecraft 版本上都一样： Effects.scale(Identifier.withDefaultNamespace("visual/fog_end_distance"), Effects.Op.MULTIPLY, 0.4F)、tint、recolor、flag （API 1.1.0）。使用游戏 EnvironmentAttribute 类型的旧写法只存在于 Minecraft 26.x，且已弃用。
  • 你自己的效果每 every 刻运行一次，并且只在有玩家在场时运行。
  • 本模组的命令可按 id 开始和停止你的事件：<command> event <namespace>:<path>。
  • 查询：running、isRunning、strength、start、stop。
  • 事件：EVENT_STARTED、EVENT_ENDED、WEATHER_STARTED、WEATHER_ENDED。
  • 陨石（API 1.5.0）。Meteors.kinds()、Meteors.drop(level, player, kind, size, natural) 与 Meteors.dropAt(...) 落下指定种类和大小的陨石；事件：MeteorEvents.LANDED。
  • 文本：event.<namespace>.<path>.name|hint、weather.<namespace>.<path>。

下界与末地的阶段

包 api.awaken。随着玩家找到裂隙和熔口，下界与末地会为整个服务器发生变化（阶段 0–4，见下界与末地）。可以读取阶段、响应阶段变化、添加“从第 N 阶段起”才会出现的事件和天气，并让自己的内容推动阶段。

  • 查询：Stages.stage(level) 和 reached(level, n) 两端可用；服务端另有 stage(server, Level.END)、enabled、 opened（已找到的裂隙或熔口 id）、places、name。仅客户端：ClientStages。
  • fromStage(n)（1–4）只用于下界或末地的事件和天气；阶段未到时日程会等待。模组命令在任何阶段都能开启它们。
  • STAGE_CHANGED 在显示的阶段每次变化时触发一次：阶段增长、stage 命令、服主开关。
  • Stages.advance(level, n, player) 让世界至少达到第 n 阶段，带模组的通知和时刻；阶段只增不减。
  • 如果服主关闭了变化，所有查询都回答阶段 0，带阶段的事件和天气不会出现。

星门与生物

api.gate 与 api.creature 包。为任意世界的星门苏醒加入你自己的条件；为你自己的世界设定星门规则；主宰事件与生物标签。

  • 条件会叠加：全部满足时星门才会苏醒。你的条件在星门窗口中显示为一行，带勾选标记。
  • 查询：Gates.conditions、Gates.worthy、Bosses.isBoss、Bosses.rank。
  • 事件：GateEvents.AWAKENED、GateEvents.TRAVELED、CreatureEvents.BOSS_SUMMONED、CreatureEvents.BOSS_DEFEATED。
  • 标签：acid_immune——酸液不会灼伤该生物；c:bosses——首领通用标签。

附属模组生物

api.creature 包。你自己的生物——附属模组的任意 Mob 类（继承游戏的羊或猪并沿用其渲染器、你自己的 GeckoLib 生物）——无需继承本模组的任何类，就能获得本模组的招式、饲养与生命图志中的页面。实体类型由附属模组自行注册；用同一 id 通过 Species.add 描述物种，再在自己的类里接上三处挂钩。

  • 招式：九种（BREATH、COIL、LOB、RAM、DIVE、LUNGE、HOWL、POUNCE、SLAM），带有公平的预警——口部发光、地面标记——随后出击并短暂休息；只会针对生物已有的目标发动。
  • 饲养：以信任驯服（主人空手下令“坐下”与“跟随”，潜行并在另一只手持驯服食物即可放生）、剪取并会再生（以及促再生食物）、治疗食物、繁育（须为 Animal）只在其故乡的天空下且不拥挤时进行。状态随生物保存，并向客户端告知“已剪、已驯服、坐下”。
  • 生命图志：已遇见、已研究（观察其活动半分钟）、样本（物品栏中有其部位）、已驯服、已繁育——每位玩家各自记录；手持星辰日志右键即可打开其卡片。文本：entity.<ns>.<path>、creature.<ns>.<path>.lore。
  • 查询与事件：Species.sheared/tamed/sitting/owner、hasMet/hasStudied/hasSample/hasTamed/hasBred、 HusbandryEvents.TAMED、SHEARED、BRED、STUDIED——同样适用于本模组的生物。
  • 未开放：坐骑、兽群、睡眠与狩猎（属于本模组生物类自身的行为）。

首领与地牢

api.creature 与 api.dungeon 包。让你的生物（你自己的类或游戏原有的生物）成为本模组的首领：带有阶段、提示与攻击预警的华丽血条、无敌的阶段转换、胜利键，以及在本模组地牢祭坛上的召唤。首领保留自己的 AI 与攻击；本模组首领的光束与粒子可供你使用。

  • 阶段：第一阶段从 1.0 开始，之后的阶段从更低的生命比例开始；每个阶段有颜色、血条下方的提示，以及可选的高光时刻。进入阶段时，首领在 transition(刻)（默认 30）内无敌，并以该阶段的颜色闪光。
  • 血条：BossBar.borrow("<模组首领>") 借用本模组某个首领的图案；BossBar.own(id, 阶段数, 紧凑) 使用你自己 GUI 图集中的精灵 <路径>_frame_<n>、_fill_<n>、_end_left_<n>、_end_right_<n>、_crest_<n>。guard() 表示巢穴守卫（紧凑血条，键 elite/<附属模组>:<路径>）。
  • 攻击预警：在描述中用 attack(名称, 文本)，在蓄力开始时调用 Bosses.warn(首领, 名称)。
  • 箭矢：与本模组的主宰和守护者一样，你的首领只承受弹射物的部分伤害，连续被命中后会在三秒内把弹射物弹回（护盾光环，近身一击即可打破）。默认与同等级、同飞行方式的本模组首领一致（主宰 0.6 与 6 次，守护者 0.5 与 5 次，飞行的 0.75 与 8 次 / 0.6 与 6 次）；自定义数值用 projectiles(比例, 次数)，projectiles(1.0, 0) 关闭。
  • 胜利：每个攻击过首领或被其锁定的玩家获得 Bosses.victoryKey(id) = boss/<附属模组>:<路径>。
  • 祭坛：在你的结构中放置带有 Dungeons.altarData(首领, 祭品, 数量, 组) 的主宰祭坛 <mod id>:boss_altar，以及带 {group:"…"} 的封印石 <mod id>:sealed_stone（或在代码中用 Dungeons.placeAltar / placeSeal）。手持祭品的玩家召唤你的首领；该组的竞技场机关苏醒，首领倒下时封印碎裂。Dungeons.openSeals 让你自己的谜题打开它们。
  • 本模组首领的外观：Bosses.beam(...)（种类 plain、prism、gaze、sun、frost、bolt、column_*…）， Bosses.particles(...) / Bosses.particle(...)（spark、mote、ring、rune、ember、frost…）。
  • 事件：CreatureEvents.BOSS_SUMMONED、BOSS_PHASE、BOSS_DEFEATED；DungeonEvents.PUZZLE_SOLVED、ALTAR_AWAKENED、 ALTAR_CLEARED。查询：Bosses.isBoss、rank、id、phase、victoryKey。
  • 未开放：本模组首领的攻击与行走、自定义光束种类、主宰的星门之心。

装备

api.gear 包：自定义武器能力与特性、带有本模组逻辑的武器和神器、由你自己的物品组成的盔甲套装。

  • Gear.addAbility(ctx, path, ability) 与 Gear.addPerk(ctx, path, perk) 按 id 添加种类；武器和神器也可以使用本模组的种类（<mod id>:wave、<mod id>:effect）并填写自己的数值。
  • Gear.weapon(spec, properties) 与 Gear.artifact(spec, properties) 返回本模组类的现成 Item，由你自己注册（Fabric：在 register 中；NeoForge：用你自己的 DeferredRegister，因为 register 在注册表之后才调用）。物品会获得按触发方式施放且有冷却的能力、改变数值的精通等级、装备提示、“按住 [G]”与详情界面。
  • 模型是你命名空间中的普通物品模型。文本：gear.<ns>.<path>.role、.ability、.ability.desc、.level.<n>、.effect（神器）、 gear.<ns>.world.<origin>、item.<ns>.<path>.lore。
  • 神器通过一个标签进入 Trinkets 与 Curios 的槽位：<mod id>:artifact_slot/necklace（ring、belt、back）。
  • Gear.addArmorSet(ctx, path, spec) 为你的盔甲物品提供套装阶段（穿戴 2–4 件时的特性与加成）。
  • 模块化盔甲（API 1.5.0）。Gear.module(ModuleSpec, properties) 创建盔甲模块（部位、重量、组、特性、加成、故乡世界）——物品由你自行注册；模块工作台按模组规则安装。 Gear.addSocketed(ctx, 谓词, SocketedItem) 为你的物品提供插槽（最多四个）。查询：sockets、fittedModules、wornModules、fitModule、worldHarmShield；事件：GearEvents.MODULE_FITTED。世界伤害以伤害类型 <mod id>:world_heat|cold|acid|radiation|void 和标签 <mod id>:world_harm 开放。
  • 查询：masteryLevel、abilityReady、wornPerks；事件：GearEvents.ABILITY_CAST、GearEvents.MASTERY_LEVEL。
  • 未开放：为你的武器使用本模组的 GeckoLib 模型、本模组自己的盔甲类。

原住民

api.natives 包：你自己的原住民民族，为任何民族加入你自己的任务（包裹、专属商品）、对话话题与交易；查询玩家与某个民族的关系；任务与交易事件。api.ringwright 包：让你的谜题或战斗成为筑环者壁龛的试炼。

  • 民族用其生物的 id 表示（"lunarian"，Natives.peoples()），职业是字符串（"elder"）。任务是 Identifier： <附属模组>:<民族>/<路径>。
  • 你的任务与我们的任务一样运作：原住民头顶的「!」与「?」、对话中的任务卡、任务窗口（F7）、屏幕角落的追踪、民族的信任。目标：bring、have、slay、key、counted（由你的代码调用 Natives.advance 计数）、check（你自己的检查）。奖励：item、xp、learn、discount、custom。文本：quest.<附属模组>.<民族>.<路径>.title、.brief、.offer、 .waiting、.ready、.done。
  • 话题的问题出现在该民族的「有什么新鲜事？」中（或用 under(...) 放在另一个话题之下）；回答中有嵌套话题、「返回」与告别。文本：topic.<附属模组>.<路径>.ask、.text。
  • 附属模组的交易在原住民达到该职业等级时加入其交易列表。
  • 查询：taken、isTaken、isReady、isCompleted、doneKey、learned、met、trust、trustLevel、people、job。
  • 事件：NativeEvents.QUEST_TAKEN、QUEST_COMPLETED、QUEST_ABANDONED、TRADED。
  • Ringwrights.pass(player, tablet) 授予 trial/<tablet>：带有 trial 条件的壁龛随后交出它的石板。

你自己的民族

自 API 1.4.0 起，附属模组可以添加一整个拥有自己身体的原住民民族：GeckoLib 模型、贴图与动画，自己的职业、酋长和有名字的大师，对话台词与交易。它的成员像模组的民族一样生活：带有实时肖像的模组对话窗口、民族颜色的交易窗口、「!」与「?」标记、任务与信任、 Jade 提示，以及 JEI 和 REI 的「交易」页面。任务现在还可以把包裹送给另一个民族（你的或模组的），并以专属商品作为奖励。

  • 身体：默认模型为 <附属模组>:native/<路径>，贴图为 <附属模组>:textures/native/<路径>.png。26.3 上文件位于 geckolib/models/native/… 与 geckolib/animations/native/…，1.21.1 和 1.20.1 上位于 geo/native/… 与 animations/native/…；要支持三个版本就两套都放。模型站在原点、面朝北方，带有头部骨骼和动画 idle、move、talk、work、greet、trade。
  • 对话：没有自己的节点时，民族使用模组的简单对话——问候、新闻（你的话题放在这里）、带交易的职业节点、告别。文本键为 native.<附属模组>.<路径>.greeting、.again、.news、.news.ask、.farewell、.craft_<职业>、.people、.job.<职业>；可以加带条件的台词（NativeCondition.persona、job、firstMeeting）或整个节点（dialog）。
  • 在世界中：Natives.spawn(level, pos, people, job, talkative)、命令或你自己的结构——实体是 <mod id>:addon_native，数据为 people、job、talkative。你的民族的聚落是你自己的结构；模组的村庄仍属于模组。
  • 包裹：NativeQuestGoal.deliver(item, count, people, job)，.given() 由发布者交给玩家，.replies(...) 是收件人的台词。专属商品：NativeQuestReward.goods(job, offer)——只对这位玩家、只在交易时多出的一项交易。
  • 你的 natives.json 里也能做到：新民族（你的命名空间中带 jobs 和 body 的条目），以及给任何民族的 trades 和 topics。

空气、气候与重力

api.life 包。有没有空气、有多热、实体感受到多大的重力、宇航服里还有什么——以及改变它们。

  • 查询：Environment.breathes、airless、localHeat、gravity、weightless；Spacesuit.oxygen、charge、modules。
  • 修饰器（OXYGEN_USE、CLIMATE、GRAVITY）串联执行：每个监听器拿到的是上一个监听器的值。GRAVITY 在两端都会运行—— 只依据客户端和服务器都能看到的东西做判断（手持物品、盔甲、状态效果）。
  • 区域：自定义重力的球形区域、维度的气候规则；你自己的供气方块（holdAirSphere、holdRoomAir）能像本模组的氧气穹顶或送风机那样保持空气。
  • 标签：方块 airtight、needs_air、magnetic；物品 pressure_bound、hydrous_minerals。

附属模组的宇航服模块

一次调用即可加入你自己的胸甲模块：你的物品能像本模组的模块一样放进宇航服架上胸甲的四个模块槽，宇航服在检查自身模块的所有地方也会把它算进去。物品就是你附属模组里的普通物品，由你自己注册。

  • 规格：oxygen、charge（宇航服容量）、reserve（储存在模块物品里的自身储备：由宇航服架以 ENERGY 或 OXYGEN 补充，或 NONE）、protects（HEAT、COLD 按比例——本模组的冷却模块为 0.4；ACID、RADIATION 完全防护）、drain（防护期间每 N 刻的消耗）、tick（你自己的动作，每 N 刻一次，服务端）、hud。
  • 查询：moduleNames、hasModule 和 moduleCount 认得 "<ns>:<path>"；moduleReserve、moduleReserveCapacity、 setModuleReserve（服务端）、protectedFrom(实体, SuitProtection)。
  • 事件：LifeEvents.MODULE_SPENT（储备耗尽；穿戴者会看到提示）、MODULE_FILLED（宇航服架已将其充满）。

机器：模组的控制台与机器卡

api.machine 包。机器的能量、流体和物品仍走加载器的标准（Team Reborn Energy 与 Fabric Transfer、NeoForge capabilities）。在此之上，你的方块实体可以使用模组的控制台窗口——你描述布局，模组负责绘制（槽位、仪表弧、通道、按钮、读数、玻璃物品栏、拒绝提示与说明、 Mouse Tweaks、JEI 与 REI 以及“模组窗口大小”设置）——以及带有模组自身倍率的机器卡槽位。

  • Consoles.menuType(布局) 是工厂：把菜单类型和你的方块一起注册到你自己的注册表（Fabric 在 onInitialize，NeoForge 用你的 DeferredRegister）。在服务端用 Consoles.open(玩家, 机器, 菜单类型) 打开。
  • 方块实体实现 ConsoleMachine：一个 Container，加上 value(序号)（控制台显示的数值）、pressed(玩家, 按钮) 和 title()。文本是你命名空间下的键：gui.<ns>.press.energy、gui.<ns>.press.progress ……
  • UpgradeSlots 用两次：布局里（.upgrades(CARDS)）和机器的刻里（factor、energyUse）。
  • MachineRecipes 让你的物品进入燃料厂、珍珠液化器、低温蒸馏器和熔液泵。粉碎机和失重锻造坊读取数据包配方（<mod id>:crushing、<mod id>:crushing_by_tag、<mod id>:zero_g_forging）——无需代码。
  • MachineRecipes.addReactorFeed 用代码添加生物反应器原料；无需代码则用数据：物品标签 <mod id>:oxygen_feed/scant|poor|fair|good|rich|lush 或 <mod id>:oxygen_feed 配方。
  • 未开放：模组的共振网络（光束）、机器种类与 Mk 等级——你的机器通过旁边的模组机器（电池块、能量转换器）接入网络。

光谱

包 api.spectral。添加你自己的标准谱（带真实谱线的物质）、样品、天体的光、只有分析才能解锁的配方、矿物扫描仪能找到的矿石以及生物弱点—— 与模组自带内容使用同一个光谱实验室和摄谱仪。

  • 谱线必须真实：取自参考资料（NIST ASD）的空气中波长，强度 3（主线）、2（强线）、1（弱线）。先注册标准谱，再注册由它组成的样品；模组自带的标准谱为 <mod id>:na、ca、fe、h、co2……（Spectral.references()）。
  • 固体样品在电弧中燃烧（亮线）；气体和冰放在灯下（absorption()）。设置 reward(...) 后，已鉴定的样品可由实验室剖开。
  • 天体的光以天体的 id 注册：你的 Sky.body、你的旅行目的地或其他附属模组的天体。
  • 每次注册都会像模组目录一样接受检查：没有实验室能分析该样品、其他标准谱与其光谱吻合、标尺在错误位置也能吻合——日志中的 WARN 行会说明需要修正什么。
  • 查询：knowsReference、hasIdentified、hasMark、进度键（referenceKey、sourceKey）、composition、laboratoryFor、gate；操作 learn。事件：REFERENCE_LEARNED、IDENTIFIED。
  • 文本：spectrum.<命名空间>.ref.<路径>[.note]、spectrum.<命名空间>.source.<路径>[.note]。

射电望远镜

包 api.radio。添加你自己的射电源。脉冲星在瀑布图上表现为短划或波纹，用折叠捕获（玩家找出它的周期）；类星体的氢线和羟基线因红移而偏移，用模板梳捕获。位置用银道坐标（galactic(l, b)）或赤道坐标（equatorial(ra, dec)）给出——它在哪里升起由真实天空决定（地球北纬 40°，月球南纬 30°，轨道上全天可见；天线不低于 12°）。默认一直在播；daily(起始刻, 时长) 和 everyDays(n) 按世界时间安排。首次记录给出你的进度键、物品和星尘，还可以让摄谱仪捕获 api.spectral 天体的光（light），或给出星际地点的导航记录（navigationRecord）。射电源之间至少相距 10°。

文本：radio.<ns>.source.<path>（名称）和 radio.<ns>.source.<path>.found（记录卡片上的一行）。查询：Radio.sources()、signal、 foundKey、hasFound、isOnAir、isAboveFloor。“Wow!” 信号和快速射电暴仍只属于本模组。

开放太空

api.space 包（API 1.2.0）。太阳系中的天体、开放太空的事件、你自己的完整太空及其间的通道，以及供星际引擎前往的群星之间的地点。

  • 天体是与模组行星一样的球体：位于轨道上、某个点上或另一个天体旁（卫星）；可设表面贴图、倾角、自转周期、大气边缘和行星环。它会画在天空中，在飞船仪表上标出名字，列在星系地图上；星舰可以瞄准它、跃迁到它、飞近它并停在它的表面。天体可以在被发现前隐藏（discovery：扫描仪或飞近即可发现），也可以通往你的旅行目的地的天空（lands）或另一个太空（passage）。
  • 太空事件像太空维度里的世界事件一样按计划到来（横幅、event 命令），并在源头加上光芒（glow）、扩散的波（wave），以及每隔几刻对星舰执行的自定义动作；波对每艘船只作用一次。
  • 你自己的太空与太阳系一样运作：密封驾驶舱、带天体球的星空、仪表、扫描仪、跃迁、自动驾驶、星系地图。维度是你的数据（最简单的是使用模组的维度类型 solar_system）。星舰通过通道进入，或从你的世界的天空升空——该世界的球体就在这个太空里。光来自太空的中心：把你的恒星放在那里。
  • 群星之间的地点在获得导航记录后出现在引擎地图「星际」上——记录是对你的天空景观的拍照，或由你发放的键（recordKey()）；引擎按光年计价跃迁过去；地点的天空是双色星云与它自己的恒星。所有附属模组共用十三个地点；地点本身没有方块。
  • 星舰（Ships）：船体、燃料、对船体的打击、推力。
  • 查询：Space.bodies、body、nearest、spaces、starPlaces、discovered。
  • 事件（SpaceEvents）：SPACE_EVENT_STARTED、SPACE_EVENT_ENDED（所有太空的所有事件）、BODY_DISCOVERED、 BODY_REACHED；穿过通道是 TravelEvents.SHIP_TRAVEL 的航段 PASSAGE。
  • 文本：space_body.<namespace>.<path> 及 .facts、.near；space.<namespace>.<path>；event.<namespace>.<path>.name|hint； star_place.<namespace>.<path> 及 .kind、.about、.find、.star.<id>。表面贴图——textures/space/<path>.png。
  • 尚未开放：图鉴异常、远路、自己的小行星带与空间站。

飞船与空间站

api.space 还开放了飞船的模块插槽、各族空间站的委托板，以及你自己空间站的天文台。

  • 飞船模块 — Ships.addModule(ctx, ShipModuleSpec.of(物品id)…)。物品由你自己注册，装入通用模块插槽。在模组自带模块之上的倍率： speed、turn、hull、tank、scanner、jump、jumpCost、shield，以及 hold(格数)；kind(…) 让同一模块的各级互斥， stacks(true) 允许多个同时安装。flight(every, 动作) 在飞船有驾驶员时于服务端每 ≥ 10 刻运行你的代码。飞船界面会在物品提示下列出模块的效果。
  • 空间站委托 — Stations.addOrder(ctx, new StationOrderSpec(路径)…)：bring(物品, 数量) 和/或 task((player, takenAt) -> …)、 people(…)、in(太空)、gate(信任等级)、reward(补给, 绿宝石, 信任)、gift(…)、grants(键)。文本：station.<ns>.order.<path> 与 .goal。
  • 天文台项目 — Stations.addResearch(ctx, new ResearchSpec(路径)…)：road、minutes、knows(数量, 键…)、anomalies(数量, id…)、 cost(物品, 数量)、result(物品)、recipes(id…)。完成后获得键 Stations.researchKey(id) 与配方（在此之前工作台拒绝合成）。文本：research.<ns>.<path>.name|gives|story|data.<n>|data.<n>.hint。
  • 查询与事件：Ships.modules(飞船)、Ships.hasModule、Stations.taken(player)、Stations.researched(player, id)； SpaceEvents.MODULE_INSTALLED、ORDER_COMPLETED、RESEARCH_COMPLETED。

客户端：画质、HUD、提示、声音、高光时刻

包 api.client（仅客户端，注册 Hud.add 除外）、api.notice、api.sound 和 api.moment（两端通用）。

  • 模组画质 — ModGraphics.level()、particles(n)、cues(n)、post()、layers(n)、glow()、far(格数)、shaderPack()：玩家调低设置时，附属模组的特效与本模组的特效一同减轻。警示效果不要削减。“低”“中”“高”是预设，玩家还可以逐个调整旋钮：“自定义”时 preset() 为空， shake() 是镜头震动的比例（用它乘以你自己的震动），cinema() 表示镜头能否离开玩家的眼睛播放短片（API 1.3.0）。
  • HUD — Hud.add(ctx, 路径, HudZone, 顺序, () -> new MyElement())：每帧元素向模组的 HUD 布局申请位置，并画在分配到的地方——不会压在模组或游戏的元素上（物品栏、聊天、Boss 血条、弹窗）。尺寸和位置使用普通的界面坐标；空间不足时使用简短形式（compactWidth/Height）。请用 lambda 传入元素，而不是 MyElement::new：这样专用服务器永远不会加载它的类。
  • 提示 — Notices.send(玩家, NoticeKind.DONE, 文本)，持续的情况用 hold(...)，带进度条用 progress(玩家, 文本, 已完成, 总数)；服务端与客户端均可调用。纯客户端代码中使用 ClientNotices.show(...)。
  • 声音 — Sounds.play(level, 排除, 位置, 来源, 主音, 音量, 音调, 叠层...)：带字幕的主音，加上不带各自字幕的游戏录音叠层（Sounds.layer）。 Sounds.aircraft(ctx, "engine") / atmosphere(ctx, "ambient") 让你的声音事件服从模组的声音开关。
  • 高光时刻 — Moments.add(ctx, 路径, MomentSpec) 用模组自带的外观在一条时间线上描述一个场景（光柱、地面纹路、天空符印、场景光照、闪光、冲击波、震屏、余烬、电影镜头、“通讯频道” HUD、声音）；服务端调用 Moments.play(level, id, 位置, ...) 只发送一个小数据包，各客户端自行播放。

通过数据开放

模组的一部分无需 API，用附属模组普通的数据文件（data/<命名空间>/…）即可使用，与原版类型一样。模组的 id 按字面书写—— <mod id>:…（UnboundApi.modId()）；字段格式与附属模组所针对的游戏版本一致。

  • 结构类型（worldgen/structure/<id>.json）：<mod id>:settled——由单个模板构成、平稳且显眼地落位的建筑：地点、朝向和高度由该类型选择（游戏拼图结构的字段，外加 max_relief、search、ground、foot——建筑立足的 [x, z] 点、overhead—— 地面不得触及的 [x, z, 高度] 点、level、above、桥用的 span、gorge、upright、sole、cave）； <mod id>:settled_village——广场会寻找平地的拼图村庄（max_relief、search、radius、above、below、level）； <mod id>:deep_dungeon——建在格子网格上的多层地牢（layout）。
  • 密度函数（15 个）——可与原版函数一样用于你维度的噪声设置。带参数、用于你自己的地形：craters、rays（带溅射辐纹的陨坑）、 facets、honeycomb、iris、ribs、lineae、cells、drift。不带参数（会重现本模组的地点）：asteroids、 wanderer_region、stellar、weave、deep、geode。
  • 机器配方（recipe/）：粉碎机——<mod id>:crushing（ingredient、result、time）与 <mod id>:crushing_by_tag （from、to——标签前缀，例如 c:raw_materials → c:dusts，count）；失重锻造坊——<mod id>:zero_g_forging （ingredients——最多四个 {ingredient, count}、result、time、colors、key——配方所需的进度键）。 JEI 和 REI 会自动在本模组的页面中显示它们。
  • 在你的模板中使用地牢谜题与筑环者壁龛——本模组的方块，其记忆存于模板的方块实体数据：sealed_stone、keystone_socket、 rune_plate_1…4 与 rune_sign_1…4、beam_emitter、mirror_a/mirror_b、beam_receiver、boss_altar（记忆 group、 order、key、boss——仅限本模组的 Boss、offering、offeringCount；解开的谜题会打开 48 格内同组的封印）、 dungeon_treasury（loot——战利品表）、ringwright_niche（tablet、key——trial 等待 Ringwrights.pass，或任意进度键）。
  • 本模组村民与原住民的交易是游戏的 villager_trade 与 trade_set 数据（模组命名空间下的 trade_set/<职业>/level_<n>.json、trade_set/native/<民族>/<职业>/level_<n>.json）：数据包会整体替换文件；要给原住民追加一项交易，请用 Natives.addTrade。
  • 水培床可种植任何 CropBlock 或 StemBlock——你的作物无需注册任何东西。
  • 本模组的粒子、声音和效果按 id 存在于游戏注册表中；标签见上文 LifeTags 与 CreatureTags。

用附属模组的文件扩充模组目录

模组的九个目录也接受附属模组 jar 中普通 JSON 文件里的条目。文件格式与模组自己的目录相同，路径也相同，只是放在你的命名空间下： assets/<命名空间>/natives.json（你自己的民族、任务、交易和话题）、spectral.json（标准谱、样品、天体之光、分析后解锁的配方、扫描仪的矿石、弱点、奖励）、 research.json（天文台项目）和 moments.json（高光时刻），以及模组用来生成方块和物品的目录：ores.json、families.json（岩石家族）、flora.json（植物与食物）、decor.json 和 gear.json（武器）。

  • 模组每次启动时自己读取一次，时机是所有附属模组的 register 之后，服务端和客户端相同。条目经过与 Java 调用（Natives.addQuest、 Spectral.*、Stations.addResearch、Moments.add）相同的检查，进入同样的列表，所以文件可以引用你的 Java 代码注册的内容。日志行 Addon data <命名空间>: natives.json 1, … 显示每个文件写入了多少条。
  • 只读取附属模组的命名空间，即带有 UnboundAddon 入口点的模组。只有数据的附属模组写一个空的 register 就够了。其他模组里同名的文件说的是它们自己的东西，模组不会碰。
  • 不支持数据包。两端都从各自的 jar 读取这些目录，网络只传 id。只在服务端存在的文件会和客户端对不上，而任务卡片、光谱窗口、天文台和高光时刻都由客户端绘制。
  • id：新条目写路径（前面会加上你的命名空间）或 <命名空间>:路径。对目录条目的引用与模组文件中一样：不带命名空间的是模组的条目（"s" 是模组的硫，"lunarian" 是模组的民族），带命名空间的可以是任何人的（你自己的写 "myaddon:sr"）。物品、方块、生物和配方用游戏 id。
  • 损坏的条目不会让游戏停下。日志里会出现 ERROR Addon <命名空间>: <文件> — <条目> skipped: <原因>，文件中的其余条目照常载入。
  • 矿石、家族、植物与食物、装饰和武器在模组注册自己的方块时读取，早于任何 register。模组不创建附属模组的类就能找到它们，并用自己的代码、在你的命名空间中注册你的条目：方块、它的物品、模组的创造标签页。生物、飞船、地牢套件和盔甲不对文件开放：它们需要模组的 GeckoLib 模型和代码。这些请用你自己的注册加上 API（Species.add、Bosses.register、Ships.addModule、Gear.addArmorSet）。

natives.json 中的任务只需要 id 和 goals。默认 giver 为 *（该民族的任何成员），repeat 为 0，文本键为 quest.<命名空间>.<民族>.<id>.title|brief|offer|waiting|ready|done。在模组之外，任务的名字是 <命名空间>:<民族>/<id>。

research.json 的内容是 {"projects": [{"id", "road", "minutes", "colour", "result", "recipes", "data", "items"}]}， moments.json 的内容是 {"moments": {"<名字>": {"duration": …, "beams": […], …}}}。两者的字段与模组自己的文件和上面的 Java 构建器相同。

附属模组自己提供什么

方块或物品由模组注册，但它的数据由你提供，放在你的命名空间。模组的生成器只写模组自己的命名空间。

  • 方块状态、方块和物品模型（26.x 用 items/<路径>.json）、纹理和 lang：block.<ns>.<路径>、item.<ns>.<路径>，描述行用 .lore。
  • 方块战利品表（data/<ns>/loot_table/blocks/<路径>.json）——没有它，方块什么也不掉。
  • 标签：mineable/pickaxe、needs_iron_tool、c:ores、c:raw_materials/<x>。有了最后一个，粉碎机的 crushing_by_tag 会自己粉碎你的粗矿。
  • 配方。
  • 矿脉：你的 configured_feature 和 placed_feature。要把它们加进生物群系（包括模组世界的），用 NeoForge 的生物群系修改器（neoforge:add_features）或 Fabric 的 BiomeModifications.addFeature。
  • 在 1.21.1 和 1.20.1 上，植物和玻璃的渲染层：NeoForge 和 Forge 在模型里写 render_type，Fabric 用 BlockRenderLayerMap。

矿石的 raw 和 product 可以是新物品（路径），也可以是完整 id 的现有物品（minecraft:raw_iron）。武器使用模组的能力和精通，模型用你自己的普通物品模型。武器的文本键为 gear.<ns>.<路径>.role|ability|ability.desc。
