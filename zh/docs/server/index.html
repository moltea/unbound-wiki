在服务器上游玩

专用服务器上的本模组：安装、多人同玩与服务器负载。

本模组为和朋友一起玩而设计：所有内容都能在有多名玩家的专用服务器上运行。

  • 服务器和每位玩家都要安装——模组及其依赖的版本相同，Minecraft 版本相同（26.3、1.21.1 或 1.20.1），加载器也相同：Fabric、NeoForge 或 Forge（见“安装”）。 1.20.1 服务器运行于 Java 17，1.21.1 服务器运行于 Java 21，26.3 服务器运行于 Java 25。
  • 每人走自己的路：日志、已发现的世界、宇航服、任务和各族的信任都是每位玩家各自的。世界、建筑和星门则是共享的。
  • 一起行动：可以同乘一枚火箭、同驾一艘飞船、换乘到朋友的飞船上，以及拖走被击落的飞船。
  • 座位会等你：如果你在一艘并非独自驾驶的飞船上退出游戏，座位仍归你—— 回来时你又在船上，坐在自己的位置，无论飞船那时已飞到哪里。船员也能挺过服务器重启：飞船还在原处，人人各就各位。独自在船上时，飞船仍会像以前一样随你离开世界、随你返回。火箭、裂隙梭舟和带乘客座的下潜钟也是如此：在升空时退出，回来时你就坐在原位，无论飞行器正飞在哪里；如果它已在你不在时着陆，你会走出舱外，站在它旁边，和其他人在一起。如果飞行器已不复存在（你离开期间飞船被摧毁），你会被送到安全处——附近的地面或你的重生点；如果你的座位已被占，飞船会让你登船，站在甲板上。屏幕上会有一行字告诉你。
  • 服务器负担轻：模组不会每刻遍历所有方块和实体，繁重的工作做得更少、只在事件发生时进行，数据包只在有变化时发送。这一点通过在有玩家的服务器上实测来检验。
  • 高速飞行不会卡住服务器：飞船航线上的区块会提前准备好，仍在生成的区块服务器不会在一刻之中停下来等待。生长中的浮岛下的光照和主宰的光束都节制地发送—— 一个数据包，以关键帧传送。
  • 客户端只负责绘制和发送意图——由服务器裁决：世界是否被发现、阶段是否算完成、火箭是否抵达。

写给管理员

两名玩家实测。发布前，整个模组都由两名玩家在真实的专用服务器上完整走一遍， Fabric 和 NeoForge 各一次：63 个场景，从加入游戏、机器界面到飞船、小世界及其事件、远方之路和终章，期间玩家会在飞行途中退出、断线，服务器也会重启。断线后和重启后，玩家拥有的一切都会逐项比对：世界和位置、进度、宇航服、任务、物品栏、脚下的飞船。

自由港之战中途停服。火卫二上劫掠者的巢穴在世界数据中记录着它还剩多少飞船和炮塔、每位玩家对它们造成了多少伤害。服务器重启后，幸存的守军会重新出动，停服前参战者的份额也完好无损。攻陷自由港的日志钥匙也会等待那些与守军交过手、但在自由港陷落时不在线的玩家：他们加入游戏几秒后就会拿到。份额物品本身会在自由港旁留存十二分钟（被击落的劫掠者残骸旁——三分钟），服务器重启也不会清除它们：战利品保存在世界数据中，每份都只等它自己的玩家，别人拿不走——驾船飞过，它就会进入货舱。

模组只有一条命令，名字与模组 id 相同；需要管理员权限。要替某位玩家执行，请用 execute as <player> run …。

命令作用
progress grant <key>计入一个进度钥匙：用于恢复丢失的进度。progress complete 和 progress reset 一次性设置整条日志路线
raid [count] [warn]向发出命令者的飞船派出劫掠者——立即伏击，或先预警再袭击。需要一名生存模式的驾驶员身处外太空、远离空间站
act flight [x y z] <world>乘火箭、梭舟或下潜钟“飞行”（不指定位置——则用最近的驾驶舱），经过游戏的全部检查
act jump <body>、act far auto|back <target>飞船跃迁；针脚、下潜，以及沿标记返回
act lair劫掠者巢穴的位置和状态：还有多少守军留守、多少已出动，多少玩家持有份额，谁还应得钥匙；太空中有多少份战利品在等待、共有多少物品

服务器无法启动

class file version 69.0 … up to 65.0。如果服务器一启动就崩溃，控制台显示 java.lang.UnsupportedClassVersionError: … has been compiled by a more recent version of the Java Runtime (class file version 69.0), this version of the Java Runtime only recognizes class file versions up to 65.0（Fabric 上它上方一行是 An exception occurred when launching the server!），说明服务器是用 Java 21 启动的，而 Minecraft 26.3 需要 Java 25：69 是 Java 25，65 是 Java 21（1.21.1 服务器用 Java 21 没问题——请确认服务器和模组文件对应同一 Minecraft 版本）。这与模组无关——不装模组的服务器也会同样失败。请安装 Java 25 并让服务器使用它：在托管服务上——在面板中设置（Java 版本或带 Java 25 的镜像）；在自己的机器上——在启动命令中写出 java 的完整路径（NeoForge 则在 run.sh 或 run.bat 中）。java -version 会显示实际启动的是哪个 Java。

缺少模组。Fabric：Incompatible mods found! 以及 requires version … or later of fabric-api, which is missing （或 … of geckolib …）；NeoForge：requires geckolib 5.5.7 or above. Currently, geckolib is not installed（1.20.1 上为 4.8.4 or above，1.21.1 上为 4.9.3 or above：GeckoLib 4）。服务器的 mods 文件夹需要和玩家相同的必需模组——见“安装”。
