Playing on a server

The mod on a dedicated server: installation, playing together and server load.

The mod is made for playing with friends: everything works on a dedicated server with several players.

  • Installed on the server and on every player — the same versions of the mod and its dependencies and the same loader, Fabric or NeoForge (see “Installation”).
  • Everyone has their own path: the journal, found worlds, the spacesuit, tasks and the trust of the peoples are per player. Worlds, buildings and gates are shared.
  • Together you can fly in one rocket, crew a ship, transfer to a friend’s ship and tow a downed ship.
  • Your seat waits for you: if you leave the game aboard a ship you were not flying alone, the seat stays yours — when you come back you are aboard again, in your own seat, wherever the ship has got to by then. A crew also survives a server restart: the ship is in place and everyone is seated. Alone aboard, the ship still leaves the world with you and returns with you, as before. The same holds in a rocket, the End shuttle and the Nether bell with a passenger seat: leave during lift-off and you come back into your seat wherever the craft is flying; if it has landed without you, you step out beside it, next to the others. If the craft is gone (the ship was destroyed while you were away), you are brought to safety — to the ground nearby or to your respawn point — and if your seat has been taken, the ship lets you aboard, on the deck. A line on the screen tells you so.
  • Light on the server: the mod does not walk every block and entity every tick, does heavy work less often and on events, and sends packets only on change. This is checked by measuring on a server with players.
  • Fast flight does not stall the server: chunks along a ship’s course are prepared in advance, and where they are still being generated the server does not wait for them mid-tick. Light under growing islands and boss beams are sent sparingly — in one packet and as keyframes.
  • The client only draws and sends intentions — the server decides: whether a world is found, a stage is counted, a rocket has arrived.

For administrators

Checked by two players. Before release the whole mod is walked through by two players on a real dedicated server, on Fabric and on NeoForge: 63 scenes, from joining and machine windows to ships, small worlds and their events, the far roads and the finale, with players leaving mid-flight, dropped connections and a server restart. After a drop and after the restart everything a player has is compared: world and place, progress, spacesuit, tasks, inventory, the ship under them.

A stop in the middle of the Free Haven fight. The raiders' lair on Deimos keeps in the world data how many of its ships and turrets are still standing and how much damage each player has dealt to them. After a server restart the surviving defenders come out again, and the shares of those who fought before the stop are intact. The journal key for sacking the haven also waits for a player who fought its defenders but was offline when it fell: they get it a few seconds after joining. The share items themselves lie by the haven for twelve minutes (a downed raider's wreck — three), and a server restart does not wipe them: the spoils are kept in the world data, each share waits for its own player and nobody else can take it — fly by in a ship and it goes into the hold.

The mod has one command, named the same as the mod id; it needs operator rights. To run it for a player, use execute as <player> run ….

CommandWhat it does
progress grant <key>counts one progress key: to restore something lost. progress complete and progress reset set the whole journal path at once
raid [count] [warn]sends raiders at the ship of whoever gave the command — an ambush at once or a raid after a warning. Needs a pilot in survival mode in open space, away from stations
act flight [x y z] <world>“fly” in a rocket, shuttle or bell (without a place — the nearest cabin), with all the game’s checks
act jump <body>, act far auto|back <target>a ship jump; a stitch, a dive and the return along the mark
act lairwhere the raiders' lair is and its state: how many defenders are still standing and how many are out, how many players hold a share, who is owed the key; how many spoils shares are waiting in space and how many items they hold

The server won’t start

class file version 69.0 … up to 65.0. If the server dies at once and the console shows java.lang.UnsupportedClassVersionError: … has been compiled by a more recent version of the Java Runtime (class file version 69.0), this version of the Java Runtime only recognizes class file versions up to 65.0 (on Fabric the line above it is An exception occurred when launching the server!), the server was started with Java 21, and Minecraft 26.3 needs Java 25: 69 is Java 25, 65 is Java 21. The mod has nothing to do with it — a server without mods fails the same way. Install Java 25 and point the server at it: on a host — in the panel (Java version or an image with Java 25), on your own machine — with the full path to java in the start command (for NeoForge — in run.sh or run.bat). java -version shows which Java is being started.

A mod is missing. Fabric: Incompatible mods found! and requires version … or later of fabric-api, which is missing (or … of geckolib …); NeoForge: requires geckolib 5.5.7 or above. Currently, geckolib is not installed. The server’s mods folder needs the same required mods as the players — see “Installation”.
